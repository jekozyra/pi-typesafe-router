# V1: Pi TypeSafe router

Approved scope: direct TypeSafe, Cloudflare Workers AI and Vercel AI Gateway classification; configurable provider-qualified target lists; ordered preflight fallbacks; explicit recovery with no automatic generation replay; validation, opt-in, manual override and minimal disclosure. New local repository; no publishing or installation changes.

## Implementation sequence

1. Define configuration, classifier/result contracts, bounded text projection and deterministic candidate eligibility.
2. Implement three adapters with explicit credentials, bounded requests, no retries, normalized/validated results and synthetic network tests.
3. Integrate Pi idle input routing, session invalidation, cancellation, commands and metadata diagnostics. Route only interactive idle inputs initially; headless routing requires explicit opt-in and documents preflight abort limitations. Never reroute steering/follow-ups or extension-injected work. Do not race non-cancellable pi.setModel against a timeout.
4. Add setup/validate/status/check, shadow/on/off, explicit next-candidate recovery without submitting any message. Use global config only, no secret persistence, no arbitrary endpoints or backend failover.
5. Test real Pi extension loading and lifecycle where feasible with synthetic providers, alongside deterministic unit/adapter tests. Include package smoke tests.
6. Review security/lifecycle behavior, simplify, document install/configuration/privacy/limits and leave a tested local Git repository.

## Key constraints

Classification uses raw idle input and a bounded recent text slice. Unknown/oversized/ambiguous inputs choose an explicit conservative route. Model candidates must exist, satisfy scope, modality and conservative context constraints; auth presence is not remote health. Vercel evaluation differs from chat APIs. Native Pi auth reuse is optional and must explicitly use a configured provider.

Preflight cancellation must stop the original input (handled), not fall through. Normal hook exceptions are swallowed by Pi, so failures must return deliberately. During async setter auth resolution, we cannot cancel the setter; serialize selections and report this host limitation. No automatic replay or provider-health claims.

## Verification

Config strictness, answer validation, fallback order, images/history, context budget, malformed/oversized HTTP bodies, auth/error sanitization, deadline/abort distinctions, all adapter payloads, Vercel confidence extraction, stale responses, manual control, shadow mode, session reset, no retries/messages on generation failure, production tarball contents, typecheck and offline test suite. No paid/live API calls without authorization.
